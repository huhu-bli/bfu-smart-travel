# 路线编辑与本地状态恢复

本批保持现有界面、工具、数据库和规划器分层，修复上线审计记录中的重复编辑和全局计划缓存问题。不修改数据库结构，不增加依赖。

## 路线更新保护

- 北京路线查询候选和更新高德交通期间，全局计划显示“正在更新路线”，暂停目的地增删、应用编辑与数据库地点发起的另一次规划。
- 同一更新完成或失败后恢复编辑。正在更新时再次触发的修改不会排队；用户应等待状态结束后再次操作。
- Agent 生成新计划或手动切换校园计划会使旧更新失效；旧请求不能覆盖新计划，也不能清除新计划正在进行的更新状态或错误。
- 失败时保留原先已经保存的计划，展示错误后允许重试。更新过程先生成本地估算，再更新高德交通，不改变用户选定顺序。

互斥与版本判定位于 `src/lib/routeUpdateGate.ts`，由 App 管理当前更新；展示组件只接收 busy 状态，不自行查询或维护第二份全局计划。

## 本地数据恢复

`src/lib/storedState.ts` 负责读取时的结构验证，`useLocalStorage` 继续负责当前浏览器的保存。字符串偏好、收藏和清单不会把 null、对象或混合类型数组当成合法值。

全局校园/北京计划验证必要字段、站点列表、停留与交通数值、节奏和选项；不能只因为 JSON 语法有效就直接渲染。损坏时仅让对应状态回到默认值，不清空整个浏览器存储。已知的无 kind 校园旧格式会在读取时迁移；有效城市计划、人工增删与顺序保持不变。未知 kind 不猜测兼容。

本批没有对历史聊天记录的独立保存格式进行完整迁移，也没有提供账号云同步或跨设备计划合并。这些仍是后续工作。

## 验证与发布

79 项测试、TypeScript 检查和生产构建通过。新增测试包括：

- 相同更新等待数据库期间，不再启动第二次修改；失败后可继续操作。
- 已被新计划取代的旧请求，不能覆盖新路线或解除新请求的锁。
- 保存过的城市计划、人工选择与已知旧校园计划恢复后内容保持一致。
- 畸形嵌套地点、路线数组或道路轨迹恢复默认值。
- 用真实 App 组件读取 null 兴趣、对象收藏与损坏全局计划缓存，实际渲染仍成功。
