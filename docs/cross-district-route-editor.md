# 跨区路线编辑

## 用户流程

在北京城市路线中点击“编辑路线”，按地区或关键词从数据库查找目的地。查询每页 12 条，可翻页；跨地区搜索和翻页时已选地点仍保留在列表中，取消后重新编辑则恢复已保存计划。应用时按照勾选顺序规划，至少保留一站。

例如：原计划只有西城区牛街，切换到东城区搜索故宫并勾选，再搜索陶然亭，可以保存“牛街 → 故宫 → 陶然亭”的跨区主线。超出时间预算时仍保留明确选中的站点并提示超时，不自动删站。

## 分层与一致性

- 界面只管理搜索、分页及未保存的勾选；查询复用 `useCityPlaces` 和只读数据库接口。筛选改变或组件卸载会取消旧请求，查询失败可重试。
- `src/lib/beijingRouteEditor.ts` 先按选中 id 向数据库确认可用记录，再按这些地点的真实行政区重算范围，最后调用现有规划器。旧单区筛选不再截掉外区选择。
- 一次最多 100 个明确目的地；数据库候选仍遵守已有分页限制。不添加未收录地点，不让千问补造坐标或资料。
- 无效、已归档或查询不到的选中 id 会使本次修改失败并保留已有计划，不假装保存成功。实际应用仍受上一批更新锁保护，旧请求不能覆盖新计划。
- 高德交通细化与全局保存继续由 App 负责；没有新增数据库写入接口或改变 Agent 框架。

## 验证与边界

81 项测试、类型检查和生产构建通过。新增真实 SQL 集成测试验证跨区按 id 查询、重复选择去重、指定顺序、预算超出提示、移除外区站后缩小范围，以及已归档地点导致整次编辑被拒绝。

本批未完成浏览器交互或手机真机验收；移动端复用已有单列筛选栏与分页样式。搜索结果来自现有资料库，不代表北京全部地点；开放和预约状态仍需另行确认。

代码位于 `feat/cross-district-route-editor`。提交和测试完成不代表部署完成。上一批路线状态保护通过 PR #22 单独处理。
