# 2026-10-23 继续测试与修复

本轮从已发布的 PR #26 继续，重点检查 AI 等待、多轮工具调用、异常地图结果和路线中的开放信息。测试使用模拟上游与真实路线计算；线上仅低频查询景点与健康检查，未进行压力或付费额度耗尽测试。

## 修复

| 问题 | 复现方式与修复 |
| --- | --- |
| 浏览器 AI 请求只对响应头计时 | 返回响应头后让 JSON 正文挂起。现在 50 秒预算覆盖完整正文读取，超时返回可恢复的错误；无效的成功响应不再被当作空答案。401/403/429 保留原状态，不掩盖鉴权与额度问题 |
| 长对话消息条数超出后端上限 | 10 轮带工具对话可超过代理的 30 条限制，原来只按用户轮数和字符数裁剪。现在同时约束条数，每次工具返回后重查，整轮移除旧历史，保留当前工具调用与结果配对；单轮过大时在本地说明需缩小范围，不发送截断的无效工具链 |
| 健康检查地址和正文判断错误 | 原函数检查 API 前缀，可能收到网页而误报成功。改查 `/api/chat/completions`，验证 `ok:true`；HTML 200 不算健康，响应正文挂起也受超时约束 |
| 地图空值被转换为零 | null、空字符串、数组和布尔值可能被 Number 转为 0。现在只接受有效数值或数值字符串；拒绝越界轨迹点，不把公共交通中的步行距离当作整段距离。无效结果保留本地估算，超时长提示准确区分高德、混合和本地估算 |
| 路线与复制文本丢失开放说明 | 每个主线目的地可展开开放与预约信息；复制路线保留开放说明及未核验日期/余票的提醒。旧缓存里新增字段的错误类型不会导致渲染失败，链接仅允许无账号密码的 HTTPS |
