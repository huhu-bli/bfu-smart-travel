# 海淀智能旅行：目的地与校园插件

## 目标

系统默认服务范围是海淀区，而不是北京林业大学。用户点名高校时，Agent 只允许查询该校独立数据；未收录详细点位时必须明确提示，不能用北林路线替代。

## 两级路由

1. `travelTarget.ts` 识别目的地：海淀区或具体高校。
2. `sceneRouter.ts` 识别任务：校园路线、点位讲解、海淀旅行、天气或帮助。

这两个维度共同生成对话键，例如：

```text
campus-route:bfu
campus-route:bjtu
outside-trip:haidian
```

因此不同学校的对话历史和本地助手记忆不会混在一起。

## 校园注册表

`src/data/campuses/index.ts` 保存学校的稳定元数据：

- `id`：工具层使用的唯一校园编号。
- `aliases`：用户可能使用的全称和简称。
- `defaultGateId`：默认入口。
- `spots`：该校独立点位数据；没有此字段就禁止生成内部路线。
- `mapMode`：专用校园地图或海淀综合地图。

新增高校时，新建独立点位文件并在注册表登记，不修改其他高校的数据。

## 三层防串校

1. 目的地路由先锁定用户要求的学校。
2. 工具参数强制要求 `campus_id`。
3. `toolExecutor.ts` 以锁定目标为准再次校验，模型传错学校时拒绝或纠正，不读取另一学校的数据。

北京林业大学与北京交通大学共用路线算法，但输入点位数组完全独立。算法复用不等于数据混用。

## 扩展规则

- 海淀综合 POI 放在 `haidianPlaces.ts`，用于区级发现。
- 校园内部点位放在 `data/campuses/<campus>.ts`。
- 提示词只描述行为和边界，不写死景点列表。
- 开放时间、预约政策和票价需通过可更新的数据源维护，并在页面提醒以官方公告为准。
- 校园专用地图只有在坐标与交互适配完成后再启用；否则使用海淀综合地图入口。
